# Enforced quality gates

Run checks with the dedicated `.quality-venv` so Gana's earlier `.venv` reference
baseline remains unchanged. The same runner is used by VS Code, tox, CI and
blocking Git hooks. Reports go to unique directories under `quality/runs/`.
The current checkout requires its native extension. Source installation needs
Rust/Cargo 1.88 or newer and a platform linker; CI pins Rust 1.88.0. A compatible
wheel includes the extension. Leave `GANA_BACKEND` unset for all normal checks.

```sh
python3.13 -m venv .quality-venv
.quality-venv/bin/python -m pip install -e '.[test,quality,docs]'
git config --local core.hooksPath .githooks
.quality-venv/bin/python tools/quality.py all
```

For Energia, install the sibling private Vael checkout first with
`python -m pip install -e ../vael` in the selected environment. Its quality extra
uses Gana 1.0.14, the release verified against Energia's regression suite.
Vael remains private; CI requires a read-only `VAEL_READ_TOKEN` secret for
Energia to check it out. Do not substitute a public repository or publish Vael
as a workaround. Repository secrets are not included in baseline reports.

## What fails the gate

- Pytest failures, with fixed Hypothesis seed 20260928 and isolated solver files.
- Statement or branch coverage below either separately configured floor in
  `[tool.research-quality]`. Initial floors round the verified baselines down
  to whole percentages: Energia 80/66, Gana 53/35, Vael 90/88. These are
  non-regression starting floors, not claims of adequate test completeness.
- Any Radon block outside A/B, including methods and nested closures. Radon
  parse errors also fail. Maintainability and raw metrics are retained as
  reports without invented thresholds.
- Ruff findings, full Flake8 findings, and Ruff formatting differences.
- Mypy errors, including checking bodies of unannotated functions. Missing
  third-party stubs are reported, not silently ignored.
- Sphinx warnings/errors and inconsistent installed dependencies (`pip check`).

Tests and plotting caches run in temporary directories. Documentation is built
from a disposable copy, including its root-level include targets. Autosummary
may regenerate API pages only in that copy. Notebooks are rendered without
execution, so a gate does not rerun research computations or modify saved
notebook content. Source hashes, including the README, changelog, and license,
are checked before/after each run.
All requested checks run even when earlier ones fail. Existing violations stay
visible; code is not rewritten or checks relaxed merely to obtain green status.

## Gana-specific lint policy

The user approved narrowly scoped policy changes on 2026-10-23 where generic
rules conflict with Gana's mathematical API or test conventions. These are
documented exceptions, not code repairs; keep their effect separate in reports.

- Tests retain ordinary pytest assertions and literal model inputs/expected
  values (`S101`, `PLR2004`). Both rules remain active in production code.
  Tests are included in ordinary Ruff discovery as well as the quality runner.
- The existing public classes `I` and `O` retain their mathematical names.
  Only their two modules receive the `E742` exception in Ruff and Flake8.
- `_element.py`, `birth.py` and `function.py` resolve mutually dependent model
  classes after module initialization; their local imports retain `PLC0415`
  exceptions. Moving these imports requires an import-cycle review.
- `var_test.py` checks symbolic addition with lists, so `RUF005` must not rewrite
  those expressions into unpacking. Other files retain that check.
- Seven named serialization-test modules load only pickle bytes generated by
  their own fixtures. Their `S301` exceptions do not apply to production loaders
  or other test modules. Do not introduce external pickle inputs there.

The exact file patterns are in `ruff.toml` and `tox.ini`. The quality runner
passes Flake8's configuration explicitly and runs linters from the repository
root so relative file patterns match. Tests and tool caches stay in temporary
directories. Public-signature, unused-argument, complexity, production security,
type, coverage and formatting checks remain in force.

## Reproducible measurements

`requirements/quality-macos-x86_64-py313-typing20261023.lock` records exact
package versions and wheel SHA-256 hashes for the measured CPython 3.13.7 Intel
macOS environment.
The matching JSON manifest records platform identity and local dependency source
hashes. Other platforms/interpreters need their own independently verified locks.
The new lock does not replace Gana's original dated baseline lock or runner.

To reconstruct, use a fresh CPython 3.13.7 environment on matching macOS x86_64:

```sh
python -m pip install --require-hashes --only-binary=:all: --no-deps -r requirements/quality-macos-x86_64-py313-typing20261023.lock
# Energia also requires the exact recorded sibling Vael source checkout.
python -m pip install --no-deps --no-build-isolation -e .
python tools/quality_lock.py verify
python tools/quality.py all --baseline
```

Install the recorded local Vael checkout with `--no-deps --no-build-isolation`
for Energia. The environment verification rejects changed/missing/additional
packages, a changed lock, platform differences and changed local dependency code.
`quality_lock.py create` is an explicit reference-creation operation and refuses
to overwrite an existing lock. Preserve old references when intentionally revising
an environment. A matching baseline environment does not excuse a failing gate.

The 2026-10-23 typing successor preserves every package version in the earlier
`quality-macos-x86_64-py313.lock`, which remains available with its manifest.
It adds pinned pandas/SciPy stubs and their typing dependencies. The quality
extra installs the corresponding stub versions. PPOPT 1.6.12 has annotations
without a `py.typed` marker, so its mypy override enables analysis of its actual
source; it does not ignore missing imports or errors in Gana callers.

## Hosted activation

Workflow files and local hooks do not activate unpublished remote workflows.
No commits or pushes are performed by this setup. Codecov uploads are configured
to fail on errors; repository connection/credentials must be supplied separately.
Codacy configuration does not itself install or authorize the external service.
Private Vael branch protections require GitHub Pro, as confirmed by GitHub's
HTTP 403 response. Its visibility stays private. Existing Gana owner controls
and required status-check names are preserved.

## Automatic function profiling

Every repository pytest invocation loads the root `conftest.py` and records a
`cProfile` profile automatically, including direct pytest, VS Code test tasks,
tox, CI, Git-hook tests and the reference baseline runner. Profiling covers
fixture setup, test calls and teardown in the main thread. Collection/import
startup and work inside other threads or subprocesses are outside this scope.
Raw stats still record time spent waiting at a subprocess boundary.

Quality runs save these files in `<run>/profile/`:

- `profile.pstats`: raw Python profiler data, readable with `pstats` or SnakeViz.
- `profile.txt`: project functions ranked by self time and cumulative time,
  with call counts and the largest comparable increases.
- `profile.json`: all measured functions and caller edges, test outcomes,
  package origins, source hashes, host/runtime and instrumentation metadata.
- `comparison.json`: function-level changes against the newest compatible
  successful run, or an explicit reason that no valid comparison is available.

Direct pytest runs write unique directories under `quality/profiles/`. That
folder also contains small history pointers to completed profiles. Existing
reports are never overwritten. To select fresh output or a reference explicitly:

```sh
.quality-venv/bin/python -m pytest tests --function-profile-output /tmp/new-profile
.quality-venv/bin/python -m pytest tests --function-profile-reference /path/to/prior/profile.json
```

`PYTEST_FUNCTION_PROFILE_OUTPUT` and `PYTEST_FUNCTION_PROFILE_HISTORY` let an
outer runner choose artifact and history locations. Distributed pytest workers
write separate worker subdirectories; the reports do not merge worker profiles.
The configured quality tasks supply the output path automatically. Failed or
empty runs retain their profiles and failing exit status, but are not eligible
as automatic comparison references.

Comparisons require matching collected tests, test/data hashes, phase outcomes,
host, Python, non-project dependency versions, thread/locale settings, Hypothesis
seed, loaded implementation identity and profiling/coverage instrumentation.
Gana's identity comes from the loaded extension's `BACKEND` value; it is recorded
as unavailable when that module is not loaded, without importing it for profiling.
The historical `GANA_BACKEND=rust-parameters` alias is not a separate workload.
Extension bytes remain in source hashes. Old profile records are preserved and
their missing implementation metadata prevents incompatible comparisons.
Package source changes are recorded
but allowed: those are the changes being investigated. Qualified project function
names survive shifts in source line numbers. Anonymous expressions retain
line-based IDs, so moving them can appear as additions/removals; inspect their
named callers as well. An initial run or changed test suite
has no compatible prior reference until the same workload has been recorded.
History selection is diagnostic and never promotes a release benchmark baseline.

Self time excludes callees. Cumulative time includes them and overlaps between
rows, so cumulative times must not be added together. Call-count changes and self
time per call help distinguish extra work from a more expensive implementation.
These profiles include profiler overhead and, for coverage tasks, coverage
instrumentation. Headline performance comparisons continue to use the separate
uninstrumented benchmark workers. The profiler adds no runtime package dependency.


## Shared Python formatter

Ruff 0.16.9 is the sole Python formatter for this repository. Its version is
pinned in the project dependencies and enforced by `ruff.toml`; the existing
quality environment already supplies this version. VS Code uses that executable
through `.vscode/settings.json` and recommends `charliermarsh.ruff`. The Python
formatter and ruler override user-level Black settings for this project. Reload
VS Code after installing the extension if the formatter has not refreshed.

The shared style uses a 79-character target and Ruff's stable defaults.
Trailing commas are enforced by the format gate; COM812 is disabled because
its lint fix can conflict with the formatter. Repository
configuration takes precedence over editor-specific Ruff settings. Format-on-save
is enabled; automatic lint fixes and import sorting remain disabled on save.
Use Ruff's explicit organize-imports action when wanted. Black and standalone
isort are not part of the repository formatting workflow.

Tasks, Git hooks, tox and CI all use `tools/quality.py`. The format gate checks
without rewriting files. CI installs the pinned Ruff dependency through the
quality extra. For an intentional formatting edit, run:

```sh
.quality-venv/bin/python -m ruff format path/to/file.py
```

Flake8 remains an independent blocking compatibility check, not a formatter.
Its checks are not identical to Ruff's configured rules; in particular, it retains
strict E501 line-length checking while Ruff's formatter uses a best-effort target.
Both read explicit repository configuration in the quality runner. Mypy, Radon,
tests, coverage and documentation gates retain their existing requirements.
Historical lock files and measured baseline reports are preserved unchanged.

## Single-backend CI and editor tasks

The Quality workflow runs all Python gates, including native binding integration,
once for each Python version (3.12 and 3.13). The Native backend workflow retains
its existing job matrix and check names while running Rust core tests, fmt,
Clippy, complexity and core coverage. It no longer duplicates the Python suite.
Both workflows retain failure artifacts; Quality retains its Codecov upload.
Read the Docs installs the pinned compiler before building the source package.

Use the ordinary Test Coverage or All Quality Checks task for native owners.
Native Quality remains a separate task for distinct Rust gates. The historical
Reproducible Baseline task and its preserved environment remain available for
their frozen sources; they are not a substitute for current native build checks.
